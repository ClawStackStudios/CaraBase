## 2024-05-18 - [SQL Injection via Missing Type Sanitization in Schema Builder]
**Vulnerability:** Found a SQL injection vulnerability in the dynamic schema builder endpoint `systemApi.post('/tables')`. The code sanitized table names and column names using `safeIdent` (stripping non-alphanumeric chars), but directly interpolated the user-provided column type (`c.type`) into the `CREATE TABLE` query. This allowed attackers to craft payloads like `INT); DROP TABLE users; --` within the column type.
**Learning:** Even when developers remember to sanitize identifiers (tables, columns) in dynamic SQL, they often forget to sanitize metadata like data types. This is particularly dangerous in schema builder APIs where full table definition objects are passed from the client. The gap existed because `c.type` wasn't perceived as an identifier in the same way as a column name.
**Prevention:** Always validate and sanitize ALL parts of a dynamic SQL statement, including structural elements like column types. For data types, using a whitelist of allowed types (e.g., `['TEXT', 'INTEGER', 'REAL', 'BLOB']`) is even more secure than regex sanitization, though applying the same `safeIdent` (alphanumeric/underscore only) effectively mitigates injection in this specific context.
